# Render-Core Infra Decisions — hb-gpu build + GL-in-CI testing

**Date:** 2026-06-11
**Purpose:** De-risk the two new infra challenges introduced by the custom-WebGL2 + hb-gpu render-core decision, before speccing RC-1. Both resolved; one P3 probe deferred into RC-1.

## Challenge 1 — Emscripten hb-gpu build: RESOLVED
- **Build the HarfBuzz amalgamation** (`src/harfbuzz-world.cc`) with a `config.h` that sets `#define HB_HAS_GPU 1` (the only define needed — it pulls in `hb-gpu-draw.cc`/`hb-gpu-paint.cc`/`hb-gpu.cc`) + `HB_TINY 1`, and a `config-override.h` that **`#undef`s `HB_NO_DRAW`, `HB_NO_PAINT`, `HB_NO_COLOR`, `HB_NO_VAR`, `HB_NO_METRICS`** (HB_TINY strips these; GPU mono needs DRAW, COLRv1 needs PAINT+COLOR, variable fonts need VAR, atlas placement needs METRICS). **`-std=c++17`** (not c++11), `-Oz -flto`. hb-gpu graduated from experimental at 14.0 — no `HB_EXPERIMENTAL_API` needed.
- **Pin (CLAUDE.md §1):** emsdk exact version (verify a 3.1.7x that builds 14.2.0 cleanly with `-flto`); HarfBuzz **commit SHA** behind tag `14.2.0` (capture `git rev-parse 14.2.0^{commit}` — tags are mutable); the exact `em++` flags are part of the pin.
- **Hybrid artifact strategy:** a dedicated `Dockerfile.hbgpu` / build stage with pinned emsdk+HB produces `hb-gpu.{wasm,js}`; **commit the artifact + `.sha256`** to the repo (e.g. `frontend/src/render/wasm/`); a CI job rebuilds from pinned SHAs and asserts checksum-stable. **emsdk stays OUT of the primary dev container** (keeps `./dev.sh` lean); a separate infrequent `build-hbgpu` step rebuilds. Day-to-day consumes the committed artifact.
- **Bindings:** hand-written `extern "C"` + `_malloc`/`HEAPU8` heap transfer (Penpot pattern), NOT Embind (size). Minimal export surface: `hbg_session_create(sfnt,len,faceIdx)`, `hbg_session_set_variations/set_size/is_color/destroy`, `hbg_shape(utf8,features)`→ packed 24-byte glyph records `{gid,cluster,x_off,y_off,x_adv,y_adv}`, `hbg_encode_glyph(gid)`→ RGBA16I blob + extents, `hbg_shader_vertex_glsl/fragment_glsl` (static — never free), `hbg_free`. JS owns/frees shape arrays + blob copies; shader strings are static; session owns its sfnt copy.
- **ONE module** (shape + gpu draw + paint), not two — reusing harfbuzzjs for shaping + a separate GPU module duplicates the shaping core (~2× bytes). Keep `HB_HAS_SUBSET` OUT (subset is a separate, lazily-loaded concern for export). Estimated **~150–180 KB gzip** — measure the real artifact in RC-1.
- **COLRv1 + variable + OT features** confirmed on with the flags above. Bitmap color fonts (CBDT/sbix/PNG) unsupported by hb-gpu (outline/COLR only — fine).
- **Fonts-1 integration:** embedded/loaded sfnt ArrayBuffers feed directly via `hb_face_create` (heap-copy → `hbg_session_create`); no decode for TTF/OTF. (Fonts-1 is sfnt-only; WOFF2 decode stays in Fonts-2.)
- Reference: `spikes/hb-gpu/harfbuzz-world.cc/` (`scripts/build.sh`, `src/config*.h`, `src/bindings.cc`) + the hb-gpu API in `spikes/hb-gpu/demo-index.js`.

## Challenge 2 — GL-in-CI golden testing: RESOLVED (1 probe deferred)
- **Playwright (pinned exact) + headless Chromium + SwiftShader** for real WebGL2 + WASM on a GPU-less Linux container. Launch flags: `--use-gl=angle --use-angle=swiftshader-webgl --enable-unsafe-swiftshader --no-sandbox --disable-gpu`. (`--enable-unsafe-swiftshader` is mandatory post-Chrome-M137/138 or WebGL2 context creation fails.) **Node `headless-gl` is disqualified — WebGL1 only.**
- **Read goldens via `gl.readPixels`** (exact, compositor-free), not `screenshot()`. Pin `premultipliedAlpha`/`alpha` in the test context; prefer `alpha:false` for goldens to sidestep premultiplication.
- **Diff:** pixelmatch (Vitest-native), start strict `threshold:0.1` / `allowedMismatchedPixelRatio:0.01`; relax toward three.js's `0.2`/`5%` only if SwiftShader edge-AA proves flaky.
- **Runner:** Vitest 4 browser mode + Playwright provider (frontend already uses Vitest); custom in-test `readPixels→PNG` harness for renderer-exact goldens.
- **Pin (CLAUDE.md §1):** Playwright exact version (transitively pins Chromium); Docker base = Playwright's official image **by digest**; the `./dev.sh` dev container is/extends that image so local == CI render env. A Playwright/Chromium/base bump is a **deliberate golden-refresh PR**, never auto-accept.
- **WASM in test:** serve `.wasm` as `application/wasm` (Vite does by default) so `instantiateStreaming` works; assert instantiation succeeded (don't let a silent ArrayBuffer fallback mask a regression).
- **Determinism caveat:** SwiftShader is consistent across hardware (no GPU driver variance) but not bit-exact across CPU microarch / SwiftShader versions (AA/FP) — mitigated by tolerance + version-pin + deliberate regen.
- **⚠️ Open probe (do in RC-1, before claiming P3 golden coverage):** whether SwiftShader honors `drawingBufferColorSpace='display-p3'` headless and what `readPixels` returns for a P3 buffer. Probe: set P3, clear to known P3-red, `readPixels`, assert bytes. Outcomes → design: (1) P3 honored → P3 goldens w/ colorspace metadata; (2) sRGB-converted readback → sRGB goldens + P3 as upstream encoding concern; (3) P3 ignored headless → P3 parity covered by **Rust color-math unit tests** (Spec 18's P3 dispatch surface) + a manual GPU smoke, NOT headless goldens. Given PR #67's P3 silent-degradation history, gate the P3-coverage claim on the recorded probe result.

## Net
Both infra challenges have concrete, pinned, reproducible approaches. RC-1 can proceed: it specs the WebGL2 foundation + SceneRenderer seam + the SwiftShader/Playwright golden harness (incl. the P3 probe as a gating task); RC-3 specs the hb-gpu Emscripten build + binding + text host per Challenge 1.
